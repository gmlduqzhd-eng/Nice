# 담임노트 제품 기준 v0.5.0

## 교과별 학기말 종합의견 임시 작업

- ‘나이스 작업 도우미’의 기본 작업은 기존 ‘행동특성·종합의견’이다. 별도의 ‘학기말 종합의견’ 탭에서 작업 학년도·학년·반·학기·교과를 선택한다. 초기 학급은 현재 `data.classroom`이며, 예를 들어 5학년 2학기로 바꿔도 기존 관찰 기록의 학급 표시는 바뀌지 않는다.
- 현재 가상 명부만 사용하고 학생별 학기말 문장을 직접 작성한다. 행특 문장·상태·관찰 근거를 자동으로 가져오지 않으며 AI를 호출하지 않는다. 학기말 문장에는 별도의 교사 검토 확인이 필요하고, 검토가 끝나며 기본 점검 문제가 없는 선택 학생만 내보낸다.
- 기존 도메인의 빈 문장·다른 학생 이름·중복 문장 점검을 재사용한다. 교과·작업 학급·명부·문장 변경은 학기말 검토를 취소한다. 파일 생성과 화면 입력으로 행특의 검토·복사·반영 확인 상태를 바꾸지 않는다.
- 학기말 작성 자료는 임시 세션이다. 작업 종류 탭 전환 중에는 유지하지만 다른 메뉴 이동·새로고침·창 닫기로 소실된다. 브라우저 저장·클라우드 백업·지속 기록 관리를 추가하지 않으며, 작업 파일로 보관하라는 안내를 표시한다.
- 학기말 작업 파일은 `{format: 'damim-neis-job', version: 2, task: 'semester-subject-opinion', subject, createdAt, classroom, rows}`이다. `subject`는 필수 한 줄 교과명(공백 정리·NFC, 40자 이하), `classroom`은 학년도·학년·반·학기, `rows`는 선택 학생의 번호·이름·수동 문장만 담는다. 행특 작업(v1)과 기존 백업(v2)을 혼용하지 않는다.
- 학년도 2000~2100, 학년 1~6, 반은 한 줄 20자 이하 문자열, 학기는 1 또는 2를 지원한다. 파일은 1MB 이하·최대 500명·문장 6,000자 이하이며 지원하지 않는 제어문자를 거부한다. 생성 후 24시간이 지나면 새 파일을 받아야 하며 원본 변경은 기존 파일에 자동 반영되지 않는다.
- 학기말 화면 연결은 `role=grid` 안의 정확한 다섯 열을 확인한다. 첫 열은 ‘선택’ 또는 체크박스가 있는 빈 선택 헤더이고, 나머지는 순서대로 ‘반/번호’, ‘성명’, ‘참고자료’, ‘학기말종합의견’이다. 다섯 셀을 가진 학생 `role=row` 중 `aria-selected=true`인 행이 하나여야 하며 번호·이름·일반 문장 입력칸은 그 행의 정확한 셀에 있어야 한다. 학년도·학년·반·학기·교과도 파일과 별도로 정확히 대조한다.
- 보이는 ‘학생부 반별 마감됨’ 안내는 추가 확인이 필요한 상태로 표시하고 학기말 입력을 중단한다. 화면 대조는 나머지 학급·교과·학생·입력칸 검사를 진행하되 입력 준비와 버튼 활성화를 하지 않는다. 기존 문장 덮어쓰기 차단은 유지한다. 해당 안내만으로 교과 의견이 수정 불가능하다고 판정하지 않는다. 교사가 나이스의 현재 상태와 절차를 직접 확인해야 한다.
- 가상 학기말 연습 주소는 `/neis-practice?task=semester`이다. 2026-09-30 실제 화면은 구조만 읽기 전용으로 확인했으며 최신 확장의 사용자 프로필 설치·실제 입력·저장·자동 저장 여부는 미검증이다. 실제 학생 이름·교사·학교·문장 원문을 소스·테스트·문서·로그에 복사하지 않는다.

## 실제 나이스 화면 연결 준비

- 작업 파일 없이 최상위 화면의 보이는 일반 입력칸·iframe·캔버스·편집 영역을 점검한다. 사용자가 선택한 입력칸의 구조를 확인하되 문장·학생 값은 읽지 않는다.
- 연결 점검 결과는 일반 입력칸 후보 또는 추가 확인 필요로 표시한다. 실제 나이스 호환성이나 저장 성공으로 표시하지 않으며, 점검만으로 입력 버튼을 활성화하지 않는다.
- 추가 확인이 필요한 경우 기존 고정 원인 코드별 한국어 사유·조치를 패널에 표시한다. 미지 코드는 고정 일반 안내로 처리하고 입력칸을 새로 선택하거나 재점검할 때 오래된 목록을 갱신한다. 학생 값·화면 원문·오류 원문은 안내로 가져오지 않는다.
- 연결 점검 JSON에는 고정된 버전·화면 종류·요소 개수·구조 불리언·원인 코드만 포함한다. 주소·DOM·셀렉터·속성 원문·학생/학급 정보·문장·작업 파일·오류 메시지는 넣지 않는다.
- 실제 화면의 입력칸 구조와 저장 흐름을 확인한 뒤 해당 화면에 맞는 연결 방식을 개발한다. 로그인·인증서·비밀번호 사용은 교사가 직접 진행한다.

## v0.5 키워드 AI 초안

- ‘나이스에 입력할 문장’ 칸에 키워드를 입력한 뒤 AI 생성을 누르면 행동특성 및 종합의견 문체의 초안을 만든다. 짧게/보통/자세히 분량을 선택하고, 선택한 관찰 근거를 함께 사용할지 정할 수 있다.
- 생성 결과는 미리보기이며 교사가 ‘이 문장 적용’을 눌러야 기존 내용을 바꾼다. 적용은 일반 문장 수정과 같은 검토 초기화 규칙을 따른다. 생성 자체로 검토·복사·나이스 반영 완료를 표시하지 않는다.
- 키워드와 선택한 근거만 사용하고 입력하지 않은 활동·수상·날짜·성과를 창작하지 않도록 지시한다. 결과의 사실성과 기재 적합성은 교사가 확인한다. 관찰 근거 없이도 초안을 생성할 수 있지만 기존 검토 단계의 근거 확인은 유지한다.
- Gemini 무료 이용이 가능한 모델을 직접 호출한다. 유료 모델/게이트웨이로 자동 전환하거나 결제를 활성화하지 않는다. 무료 한도·사용 가능 모델은 공급자 정책에 따라 달라지며 API 키의 프로젝트 요금제를 운영자가 확인한다.
- 서버 전용 API 키를 사용하고 인증된 계정 요청만 수락한다. 명부에 등록된 이름은 브라우저에서 가리며, 계정 이메일·학생 ID·전체 명부를 모델 입력에 추가하지 않는다. 무료 API의 입력·출력 제품 개선 사용 가능성을 생성 버튼 부근과 개인정보 안내에 표시한다.
- 생성 중 편집·학생 변경·계정 변경·저장 충돌은 오래된 응답 적용을 막는다. 취소와 실패는 원문을 보존한다. 서버의 요청 크기·출력 크기·제한 시간·일시적 요청 제한을 적용한다.
- 실제 모델 응답과 모의 API 검증을 구분한다. API 키 미설정·공급자 한도·불완전한 응답을 정형 문장으로 위장하지 않고 오류로 안내한다.

## v0.4.2 로그인 안내와 백업 보호

- 인증 공급자가 재방문·세션 복구·같은 계정 재확인에서 `SIGNED_IN`을 보내도 새 로그인 완료로 알리지 않는다. 실제 로그인 콜백과 로그인 화면에서 계정이 새로 연결될 때만 완료 안내를 표시한다. 로그인·로그아웃 성공 안내는 4.5초 뒤 사라지고 오류 안내는 직접 닫을 때까지 유지한다.
- 백업 조회 이후 다른 기기가 수정한 자료는 저장 요청의 `user_id`·`updated_at` 조건으로 보존한다. 처음 저장할 때는 insert를 사용해 그 사이 생긴 백업도 덮어쓰지 않는다. 충돌은 자동 재시도하지 않고 JSON 보관과 최신 백업 확인을 안내한다.
- 클라우드 조회·파일 읽기 중 현재 자료가 바뀌거나 계정이 전환되면 늦은 복원 응답을 적용하지 않는다. 다른 탭 변경이나 저장 장애로 편집이 중지된 경우 내려받기만 계속 제공하고 업로드·가져오기·초기화는 중지한다.
- 이미 전송한 백업의 응답을 기다리는 중 새 편집이 생기면, 요청 당시 자료만 저장됐음을 명시한다.
- 복원 확인창에 현재/불러올 학급·학생 수·관찰 건수·문장 건수를 표시하고, 성공 후 관찰 노트에서 원문을 확인하는 버튼을 제공한다.
- DB 스키마·RLS·인증 공급자 설정은 변경하지 않는다. 충돌과 계정 전환 회귀 검증에는 합성 사용자·모의 API를 사용하며 실제 두 계정 RLS 검증으로 표현하지 않는다. 실제 나이스 화면 호환성 작업은 이번 요청에서 제외한다.

## v0.4.1 지정 오류 개선

- 수동 클릭으로 잘못 지정한 항목을 확인할 수 있도록 선택값·작업 파일 기대값을 표시한다. 문장 본문은 지정값 목록에 중복 표시하지 않으며, DOM에 textContent로만 렌더링한다.
- 정확한 공식 연습 주소와 검증용 DOM 계약에서만 일곱 항목 자동 지정을 제공한다. 중복 ID·누락·숨김·다른 화면을 거부하고 실패하면 기존 지정과 입력 준비 상태를 모두 초기화한다.
- 자동 지정은 대조·입력을 실행하지 않는다. 학생/학급 변경, 기존 문장, 입력칸 목적, 파일 만료 검사와 저장 여부 구분을 유지한다.
- 연습 페이지의 버튼으로 배포된 동일 입력 스크립트를 실행할 수 있다. ‘웹 연습’임을 명시하며 확장프로그램 설치와 실제 나이스 연결 성공으로 표시하지 않는다.

## 목적

초등 담임이 평소 관찰 기록을 누적하고, 누락을 점검한 뒤 나이스에 직접 옮길 문장을 준비한다. 같은 자료를 여러 번 찾아 입력하는 부담을 줄인다.

로그인을 강요하지 않고 먼저 기록 기능을 체험하게 한다. 사용자는 화면에서 다음 행동을 바로 찾을 수 있어야 한다. 이름·학교·비밀번호를 받는 별도 가입 양식 없이 Google 계정 선택 또는 이메일 링크로 가입과 로그인을 함께 처리한다. 각 인증 경로의 실제 이용 가능 범위를 구분한다. 계정은 수동 백업에 사용하며, 로그인 자체가 기록 전송의 동의가 되지 않는다.

## v0.4 입력 도우미 개발 범위

사용자의 나이스 자동 작업 개발 요청에 따라 행동특성 및 종합의견의 입력 보조를 추가한다. 실제 나이스 화면에 대한 검증은 별도 단계이며 가상 자료 기준을 유지한다.

- 검토 완료·복사됨 상태 중 점검 문제가 없는 학생만 작업 JSON에 포함한다. 한 학생의 초안이 여러 개이면 중단한다. 파일 생성으로 검토·복사·반영 상태를 변경하지 않는다.
- 확장프로그램은 클릭한 탭에서 파일을 읽고 사용자가 지정한 학년도·학년·반·학기·학생 번호·이름을 정확히 대조한다. 번호·이름과 입력칸은 같은 학생 편집 영역에 있어야 한다.
- 문장 입력칸은 하나의 일반 텍스트 입력칸이며 ‘행동특성 및 종합의견’으로 표시되어야 한다. 기존 내용·모호한 화면·비활성 입력·다른 학생·사라진 요소를 거부한다. 실제 나이스 전용 편집기 구조를 추정하여 연결하지 않는다.
- 대조 직후 입력 전 다시 확인하고, 입력 후 문장 유지까지 확인한다. 입력 시도 후 확인이 실패하면 변경이 남았을 수 있음을 알린다. 로그인·인증서·비밀번호·비공개 API·자동 저장 버튼 조작은 없다.
- 대상 페이지의 input 이벤트가 자체 저장을 실행할 가능성은 실제 화면별 검증이 필요하다. `/neis-practice`는 가상 화면이며 실제 나이스 호환성을 증명하지 않는다.
- 작업 파일은 최대 1MB, 500명, 문장 6,000자이며 24시간 후 만료된다. 원본 수정은 다운로드 파일에 자동 반영되지 않으므로 다시 만든다. 브라우저 확장 메모리만 사용하고 자료를 서버로 전송하지 않는다.

## v0.3의 개선과 수용 기준

- 한 기록 공간의 학년도·학년·반·학기를 수정하며, 기존 기록은 유지한다. 여러 학급 전환으로 표현하지 않는다.
- 명부 추가 시 번호·이름·중복·최대 인원을 검증한다. CSV/TSV와 엑셀 두 열을 미리본 뒤 추가하며 기존 기록을 덮어쓰지 않는다.
- 이름 수정은 학생 ID·원문·근거를 유지하고 문장을 재검토 상태로 바꾼다. 관찰이나 초안이 연결된 학생은 삭제할 수 없다.
- 로그인 전 공간과 계정 A·B 공간을 분리한다. 계정 변경 시 열려 있던 편집기와 비동기 응답도 이전 공간에 남지 않도록 닫는다.
- v1 JSON/로컬 자료는 v2로 읽되 기존 원본을 삭제하지 않는다. 소유자를 알 수 없는 이전 기록은 체험 공간에서만 연다.
- 다른 탭의 변경 감지나 저장 실패 시 편집을 멈추고 원본과 백업 경로를 보존한다. 손상된 저장 원문을 자동 덮어쓰지 않는다.
- 실제 Google 인증·원격 백업 검증은 별도이며 모의 계정 테스트로 성공을 주장하지 않는다.

## 이전 v0.2의 개선

- 상단에 ‘회원가입 · 로그인’을 두고 이메일 입력 → 메일 링크 클릭으로 단계를 줄인다. 메일을 보낸 뒤에는 재전송 대기시간, 이메일 변경, 체험 계속하기를 안내한다.
- 공통 인증 상태를 앱 시작부터 확인한다. 로그인 메일에서 돌아오면 설정 화면을 따로 열지 않아도 로그인 결과가 반영된다.
- 첫 화면에 기록 → 입력 준비 → 백업을 안내하고 필요한 작업으로 바로 이동시킨다.
- 신규 관찰에서 ‘저장하고 다음 학생’을 제공한다. 저장 성공 후 학생을 바꾸고 내용만 비우며 날짜·분류는 유지한다.
- 서비스 하단에 저작권 문구와 교사 작성 기록·오픈소스 구성요소에 대한 안내를 표시한다.

이메일 발송은 현재 기본 SMTP의 조직 팀원 제한을 받는다. 해당 무료 프로젝트는 기본 메일 템플릿 변경도 막혀 있어 숫자 인증번호 기능을 제공하지 않는다. 일반 사용자용 메일 연결은 별도 작업이며, 실제 메일 인증은 아직 검증하지 않았다. Google은 Client Secret이 필요 없는 GIS ID token 방식으로 구현·배포했고 Google 앱의 Production 전환을 확인했다. 일반 Chrome에서 실제 로그인·가상 자료 수동 저장·같은 브라우저 복원을 확인했다. 다른 브라우저의 불러오기 성공 안내는 사용자가 확인했다. 복원 원문의 직접 대조와 실제 두 계정의 접근 격리는 남아 있다. 인증 센터에서 기본 인증 범위는 데이터 접근 심사가 필요 없다고 확인했으며, 앱 이름·로고 표시용 브랜드 검증은 진행하지 않았다. 이전 Codex 내장 브라우저의 FedCM 오류 원인은 확정하지 않았다. [현재 설정과 검증 순서](GOOGLE_AUTH.md)

## 첫 버전의 데이터 흐름

가상 학생 → 관찰 기록 → 작성 근거 선택 → 원문 모으기/문장 편집 → 검토 완료 → 복사 성공 → 교사에 의한 나이스 반영 확인.

실제 나이스의 저장 결과는 조회하지 않는다. 복사는 반영 확인과 다르다. 원문이나 근거가 바뀌면 기존의 완료 상태는 해제되어야 한다.

## 구현 수용 기준

- 대시보드 숫자는 저장된 가상 자료로 계산한다.
- 관찰 기록은 새로고침 후에도 유지된다.
- 연결 근거가 없거나 내용이 비어 있으면 검토 완료할 수 없다.
- 다른 학생의 근거를 연결할 수 없다.
- 클립보드 복사가 실패하면 ‘복사됨’으로 바뀌지 않는다.
- 복사 이전에 ‘나이스 반영 확인’을 할 수 없다.
- 수정한 문장은 다시 검토해야 한다.
- 손상된 백업을 정상 자료로 덮어쓰지 않는다.
- 공개정보 연결이 실패하면 오류를 표시하고 예시 결과로 위장하지 않는다.
- Supabase 원격 저장은 로그인한 계정의 요청과 명시적인 버튼 조작으로만 수행한다.
- 로그인 창은 키보드로 열고 닫을 수 있고 닫은 후 원래 위치로 포커스를 돌린다.
- 로그인 요청이 실패하거나 오래된 요청이 나중에 끝나도 잘못된 성공 화면을 만들지 않는다. 인증 오류 원문과 토큰을 화면에 노출하지 않는다.
- 로그인·로그아웃 중 계정이 바뀌면 이전 계정의 늦은 백업 응답을 적용하지 않는다.
- 연속 기록은 유효한 관찰 저장에 성공한 뒤에만 다음 학생으로 이동한다.
- Google 공급자와 해당 환경의 origin·공개 Client ID를 준비한 빌드에서만 버튼을 표시한다. 설정 완료·모의 테스트 통과·실제 로그인 검증을 각각 구분한다.
- GIS는 nonce 검사를 유지하고 공식 Google 버튼을 사용한다. 팝업 취소나 스크립트 실패 후에도 체험 기능을 계속 이용할 수 있어야 한다.

## 다음 구현 순서

1. Google의 실제 로그인·같은 브라우저 백업 복원은 확인했다. 독립 브라우저에서는 사용자가 불러오기 성공 안내를 확인했다. 복원 원문 직접 대조, 다른 PC의 같은 계정 복원과 로그아웃 후 재로그인을 확인한다. 추가 Secret 입력은 필요하지 않다. Codex 내장 브라우저에서 관측한 FedCM 오류의 원인을 단정하지 않으며, 일반 사용자용 이메일 인증은 별도 SMTP 구성·검증 단계로 둔다.
2. 두 실제 로그인 세션의 RLS 격리를 확인한다. 나이스 인증키 설정 후 학교 조회를 별도로 검증한다.
3. 실제 나이스에서 개인정보를 제거한 내려받기/올리기 양식 확보 후 파일 매핑 설계.
4. v0.3의 학급 표시·명부 관리를 여러 학급/학년도 보관·전출 처리로 확장한다. 실제 학생 자료 사용 전 학교 사용 조건을 확정한다.
5. 월말 출결 대조와 증빙 제출 여부. 규칙은 해당 학년도와 학교 기준별로 버전 관리.
6. 운영 데이터 보유기간·삭제·감사 기록과 계정별 자료 분리 완성 후 실사용 전환.

## 보류한 항목

나이스 인증서 보관, 비밀번호 수집, 비공개 API 호출, 자동 로그인·무인 저장·학생 자동 전환, 근거 없는 AI 문장 생성, 민감한 증빙 원본 수집. 입력 보조는 기존 행특과 위 임시 학기말 범위로 개발하며 실제 화면별 호환성 검증 후 확장한다.

## 변경 작업의 기본 절차

요구사항과 수용 기준 기록 → 필요한 코드 변경 → 관련 도메인/통합 테스트 → 타입 검사·빌드 → 주요 사용자 흐름 브라우저 확인 → 검증한 버전 배포.

필요한 환경변수 이름만 문서에 기록하고, 실제 키·학생 개인정보·운영 백업을 저장소에 커밋하지 않는다.
