## 브라우저에서 확인한 흐름

1. 화면·메뉴 이동 및 오류 없는 초기 표시
2. 학생을 지정해 관찰 추가, 새로고침 후 유지
3. 반영 확인한 문장 수정 시 검토 초기화
4. 근거 원문 모으기 → 검토 → 실제 클립보드 복사 → 교사 확인 → 재수정
5. 모바일 메뉴·입력 화면과 페이지 가로 넘침 방지
6. JSON 다운로드와 확인을 거친 복원
7. 손상·다른 형식·1MB 초과 백업 거부
8. 나이스 키가 없는 상황의 503 및 연결 대기 안내
9. 누락된 근거 연결 해제 후 새 관찰 연결·검토
10. 손상된 브라우저 저장 원문을 복구 파일로 다운로드
11. ‘저장하고 다음 학생’에서 날짜·분류 유지, 학생 전환, 내용 초기화, 중복 저장 방지 및 새로고침 후 유지
12. 첫 사용 안내의 메뉴 이동·접기·다시 보기 및 저작권 안내
13. 이메일 가입·로그인 통합 요청, 로그인 반환 URL 처리와 세션 유지
14. 메일 재전송 대기·이메일 변경·요청 제한 오류
15. 로그인 창 키보드 접근·닫기 후 포커스 복귀·모바일 화면
16. 로그인만으로 전송하지 않음, 저장 취소, 명시적 저장·불러오기와 로그아웃
17. 만료된 링크 안내와 URL 오류·토큰 정리
18. 반환 URL에 오류 필드가 없어도 초기 토큰 검증이 실패하면 재시도 안내, 인증 토큰 제거, 무관한 URL 항목 보존 및 새 로그인 요청
19. Google 활성화 시 공급자·반환 주소가 맞는 인증 URL로 이동하며 비활성화 시 버튼 숨김

13~18은 합성 계정과 모의 Supabase 네트워크 응답으로 확인했습니다. 실제 메일은 보내지 않았으며 실제 계정 생성·로그인·클라우드 전송 성공을 의미하지 않습니다. 브라우저 테스트는 최초 실행 후 테스트 선택자와 반환 URL 이동 방식 등을 수정한 관련 시나리오 재실행까지 포함해 모두 통과했습니다. 18번은 수정 전 실패를 재현한 뒤 인증 초기화 오류 처리를 보완하고 인증 시나리오 6개 전체를 재실행해 통과했습니다.

## 미검증 범위

- 운영 인증키를 사용한 실제 나이스 조회
- Supabase 실제 이메일 로그인과 브라우저의 저장·불러오기 전체 흐름
- 두 실제 로그인 세션의 REST 요청을 통한 RLS 격리. 아래 SQL 트랜잭션 검증과 구분
- Supabase Advisors 및 실제 사용자용 메일 전달 설정의 검토·검증
- 배포 환경의 전체 브라우저 시나리오. 아래 초기 설정 화면 확인과 구분
- 실제 학생 개인정보 취급 요건과 학교별 나이스 입력 양식

브라우저 테스트는 기본 가상 데이터를 사용합니다. 인증 테스트는 Supabase 공개 설정이 있는 서버에서 외부 인증·저장 요청을 가로채 모의 응답하며 실제 메일·운영 데이터 전송을 차단합니다. 실제 나이스 키를 넣은 환경에서 ‘미설정 503’ 시나리오는 별도의 테스트 서버로 실행해야 합니다.

## v0.2 간편 사용 개선

- 상단 회원가입·로그인 진입점과 앱 시작 시 인증 초기화, 이메일 링크 안내·재전송, 계정 화면을 확인했습니다.
- Supabase 기본 SMTP의 팀원 주소 제한과 무료 플랜의 기본 이메일 템플릿 제한을 대시보드 및 공식 문서에서 확인했습니다. 일반 교사의 이메일 가입은 아직 제공할 수 없으며 로그인 창에 테스트 계정 제한을 표시합니다.
- Google 로그인 코드는 공개 환경변수가 정확히 `true`일 때만 표시합니다. 공급자 연결과 실제 로그인을 확인하기 전에는 활성화하지 않습니다.
- `pnpm typecheck`, 단위/API 테스트 31개, `pnpm build` 통과. 브라우저 검증 18개 통과.
- 실제 Google 계정 연결, 실제 이메일 수신과 원격 백업 검증은 남아 있습니다. [Google 설정 안내](GOOGLE_AUTH.md)를 참고합니다.

## Google 로그인 준비 후 추가 검증

- OAuth 앱·웹 클라이언트 생성 완료를 Google Cloud 화면에서 확인했습니다. Supabase Google 공급자 인증키 입력은 사용자 직접 작업 대기 상태입니다. 실제 인증 성공으로 기록하지 않습니다.
- Google 활성화 빌드에서는 ‘간편하게 시작하기’ 제목, Google 주요 버튼 및 초기 포커스를 사용합니다. 비활성화 시 기존 이메일 화면을 유지합니다.
- 인증 브라우저 테스트 7개를 Google 활성화 운영 빌드(`127.0.0.1:3001`)와 비활성화 개발 서버(`127.0.0.1:3000`)에서 각각 통과했습니다. 플래그 기대값을 명시해 버튼이 양쪽 모두 숨겨진 채 통과하지 않도록 검사했습니다.
- 추가 시나리오는 실제 클라이언트가 만든 Supabase authorize URL의 `provider=google`, 앱 origin 반환 주소, 페이지 이동을 검사합니다. 네트워크는 모의 응답을 사용하므로 Google 계정 선택·동의·토큰 교환 성공을 의미하지 않습니다.
- 타입 검사, 단위/API 테스트 31개 및 Google 활성화 빌드 통과. 운영 환경변수는 활성화하지 않았습니다.
