## 이전 OAuth 이동 방식 검증 (6251869)

- OAuth 앱·웹 클라이언트 생성 완료를 Google Cloud 화면에서 확인했습니다. Supabase Google 공급자 인증키 입력은 사용자 직접 작업 대기 상태입니다. 실제 인증 성공으로 기록하지 않습니다.
- Google 활성화 빌드에서는 ‘간편하게 시작하기’ 제목, Google 주요 버튼 및 초기 포커스를 사용합니다. 비활성화 시 기존 이메일 화면을 유지합니다.
- 인증 브라우저 테스트 7개를 Google 활성화 운영 빌드(`127.0.0.1:3001`)와 비활성화 개발 서버(`127.0.0.1:3000`)에서 각각 통과했습니다. 플래그 기대값을 명시해 버튼이 양쪽 모두 숨겨진 채 통과하지 않도록 검사했습니다.
- 추가 시나리오는 실제 클라이언트가 만든 Supabase authorize URL의 `provider=google`, 앱 origin 반환 주소, 페이지 이동을 검사합니다. 네트워크는 모의 응답을 사용하므로 Google 계정 선택·동의·토큰 교환 성공을 의미하지 않습니다.
- 타입 검사, 단위/API 테스트 31개 및 Google 활성화 빌드 통과. 운영 환경변수는 활성화하지 않았습니다.

## Google GIS 로그인 및 공개 안내 페이지

- 기존 OAuth 이동 방식은 Google 공식 버튼의 ID token을 Supabase `signInWithIdToken`으로 확인하는 방식으로 교체했습니다. 비밀키를 앱·환경변수에 저장하지 않습니다.
- Supabase Google 공급자에 공개 Client ID만 저장한 뒤 공개 Auth 설정의 `external.google=true`를 확인했습니다. nonce 검사 생략 및 이메일 없는 사용자 허용은 꺼진 상태를 유지했습니다.
- Google 활성화 빌드에서 단위/API 테스트 31개와 타입 검사·빌드가 통과했습니다. `/privacy`, `/terms`가 정적 페이지로 생성됐습니다.
- 인증 시나리오 9개와 업무 시나리오 12개가 통과했습니다. 업무 시나리오 1개는 변경된 로그인 버튼 문구에 선택자를 맞춘 뒤 재실행해 통과했습니다.
- Google 비활성 개발 서버에서는 인증 시나리오 7개가 통과했고 Google 전용 2개는 명시적으로 제외했습니다. SDK 요청이 발생하지 않는 것도 확인했습니다. 검증용 3001 서버는 종료했습니다.
- 외부 Google·Supabase 인증 요청은 모의 응답을 사용했습니다. 이 결과는 실제 Google 인증 또는 원격 백업 성공과 구분합니다.
- 개인정보처리방침·이용약관을 로그인 전에도 읽을 수 있게 연결했습니다. 데스크톱과 390px 모바일에서 확인했고, 안내 표의 가로 넘침을 수정해 페이지 너비를 초과하지 않음을 확인했습니다.
- Vercel Production에 Google 공개 Client ID 및 표시 플래그를 저장했습니다. 코드 커밋 `d4bd638`의 intended `nice_helper_ys` 배포가 Ready인 것을 확인했고, 실제 운영 주소에서 한국어 Google 공식 버튼 표시를 확인했습니다.
- `/privacy`, `/terms`의 무인증 운영 HTTP 200 및 페이지 제목을 확인했습니다. Google Branding에 홈페이지·개인정보처리방침·이용약관 주소를 저장한 뒤 성공 알림을 확인했습니다.
- 직전 확인 이력: 당시 Google Audience는 Testing 상태였고, 실제 Google 버튼 클릭 단계에서 Chrome 연결이 끊겼습니다. 재연결 후에도 자동화 목록에서 Chrome을 확인하지 못했습니다. 이후 공개 전환과 추가 시도 결과는 아래에 기록합니다.

## 2026-09-29 추가 확인: Google Production 전환과 실제 인증 시도

- Codex 내장 브라우저의 기존 Google 계정 세션으로 대상 Google Cloud 프로젝트에 접속했습니다. Audience에서 앱 게시를 진행한 뒤 **‘프로덕션 단계’와 ‘테스트로 돌아가기’** 표시를 확인했습니다. Google 앱 공개 전환은 완료했습니다.
- 인증 센터 Data access status에서 **민감하거나 제한된 범위를 요청하지 않으므로 인증이 필요 없다는 안내**를 확인했습니다. Brand는 **‘브랜딩이 사용자에게 표시되고 있지 않음’** 상태이며 앱 이름·로고 표시용 브랜드 검증은 진행하지 않았습니다. 데이터 접근 심사·브랜드 검증·앱 게시는 별도 상태입니다.
- 운영 앱의 실제 Google 공식 iframe 버튼을 Codex 내장 브라우저에서 클릭했습니다. 콘솔에 `[GSI_LOGGER]: FedCM get() rejects with NetworkError: Error retrieving a token.`이 나타났습니다. 오류 원인은 확정하지 않았으며, 일반 브라우저에서도 같은 결과가 발생한다고 판단하지 않습니다.
- Chrome은 자동화 목록에서 여전히 확인되지 않았습니다. 일반 브라우저의 계정 선택·Supabase 인증 → 가상 자료 수동 저장 → 로그아웃·재로그인 → 불러오기 검증이 남아 있습니다. **실제 Google 로그인과 클라우드 백업 성공은 아직 확인하지 못했습니다.** Client Secret 수동 입력은 필요하지 않습니다.
